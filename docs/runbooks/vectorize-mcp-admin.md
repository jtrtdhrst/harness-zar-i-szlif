## Credential handling

The gateway-only Coolify service environment variable `VECTORIZE_ADMIN_MCP_TOKEN` contains an independently generated 256-bit token. Retrieve it using Coolify's protected environment variable view. It is **not** the upstream MCP token, not a bank token, and not committed to GitHub. Append it as the `access_token` URL query parameter for clients that cannot configure a bearer header.

**Risk:** URL-embedded credentials can appear in browser history, CDN/proxy/access logs, monitoring and copied links. Do not paste the complete URL into tickets or chat; do not enable request-URL logging. Rotate the key in Coolify and redeploy/restart `hindsight-mcp` if exposure is suspected.

## Operations

- **Source of runtime configuration:** Coolify service `docker_compose_raw` for both stacks, with the gateway's Caddyfile generated by its startup command. **Do not** edit a temporary Caddyfile inside a running container: it disappears on restart.
- Inspect both stack configurations and `VECTORIZE_ADMIN_MCP_TOKEN` in Coolify after changes. Verify running backend and gateway, public HTTPS, unauthorized rejection, MCP initialize, tool count and authorized read/write.
- Preserve the existing 14 per-agent routes and bank tokens; never change the restricted original `hindsight` MCP tool allowlist when enabling administrator capabilities. The admin instance has no independent worker and no control plane.
- For rollback: restore the previous gateway compose and remove only the `hindsight-admin` sidecar configuration from the Hindsight compose; redeploy both services. **Never** remove the production PostgreSQL or OAuth volumes as part of this rollback.
