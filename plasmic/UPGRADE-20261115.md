# Plasmic — upgrade runbook (2026-11-15)

Target: move the self-hosted Plasmic from upstream pin `85b8611` (2026-10-09) to
`e2e0b74` (2026-11-15), 212 commits, 207 added / 160 removed / 1,160 modified blobs.

Status: **candidate source only.** Nothing in this document is evidence of a
deployment. Per `docs/RELEASE-POLICY.md` the release identity is the approved
source commit **plus** the immutable image digest, verified on a canary.

volume, a new volume, and a restore — a separate migration with its own backup.

## Breaking environment change

`ADMIN_EMAILS` is now parsed with `JSON.parse` as a `string[]`
(`platform/wab/src/wab/server/config.ts`). A comma-separated list makes the
container crash at boot:

```
SyntaxError: Unexpected token 's', "smoke@example.com" is not valid JSON
```

Set it in Coolify before deploying:

```
ADMIN_EMAILS=["name@domain"]
```

`MAIL_CONFIG`, if set, is also `JSON.parse`d. Neither variable is optional for
the production cutover — the app does not start without a valid value.

## Prerequisites

- Coolify API token (read + deploy) or SSH to the Coolify host.
- Free disk on the build host: ~8 GB (two images + pnpm store).
- The current `plasmic_pgdata` volume backed up (see step 2), even though the DB
  image does not change: the new WAB code runs its migrations on startup.

## Steps

1. **Record the current state** — do not touch it yet.
   ```bash
   curl -sS "$COOLIFY_URL/api/v1/applications" -H "Authorization: Bearer $COOLIFY_TOKEN"
   curl -sS "$COOLIFY_URL/api/v1/deployments" -H "Authorization: Bearer $COOLIFY_TOKEN"
   ```
   Keep: app UUID, last deployment commit, running image tag, `docker inspect`
   image digest for `plasmic-wab` and `plasmic-studio`, container start time.

2. **Back up the database.**
   ```bash
   docker exec <plasmic-db-container> pg_dump -U wab -d wab --no-owner --no-privileges > wab-$(date +%F).sql
   ```
   Verify the dump is non-empty and restores into a scratch container before continuing.

3. **Canary build, not production.** Create a second Coolify application from the
   same source with its own database volume and a non-public hostname, pointing at
   the candidate commit from this PR. Build `plasmic-wab`, `plasmic-codegen`,
   `plasmic-studio`. Expected build time: 30–60 min; watch for `pnpm install`
   resolution failures (`minimumReleaseAge`, `injectWorkspacePackages`) and for
   studio-only build steps (`html-webpack-plugin`, `build-css`, `sub/`,
   `react-web-bundle/`, `live-frame/`, `canvas-packages`).

4. **Canary smoke** (all four must pass):
   ```bash
   curl -fsS https://<canary>/api/v1/app-config | grep plasmic-zar-i-szlif
   curl -fsS -o /dev/null -w '%{http_code}\n' https://<canary>/            # 200, Studio HTML
   curl -fsS -o /dev/null -w '%{http_code}\n' https://<canary>/api/v1/codegen/health
   ```
   Then in the Studio UI: open an existing project, edit a component, publish to the
   loader-hosted endpoint, and load that published page in a browser. Login and the
   GitHub App install flow must both work (devflags `githubClientId`).

5. **Cutover** — approve the exact canary digest, deploy that digest to the
   production app, then read back: deployment ID/time, image digest, container ID,
   `/api/v1/app-config`, Studio HTML 200. Keep the previous digest for rollback.

6. **Rollback** — repoint production to the recorded previous image digest and
   restart; if migrations already ran, restore `wab-<date>.sql` into the volume.
   Both paths must be rehearsed on the canary before step 5.

Two operational notes from the smoke:

- nginx resolves `plasmic-wab`/`plasmic-codegen` at start, so `plasmic-studio`

  without errors, which is why the production `pg_dump` is mandatory before
  cutover.
